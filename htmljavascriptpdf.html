alert · prompt · confirm — Cuaderno imprimible2

1. ¿Qué es un diálogo modal?

Un diálogo modal es una ventana que el navegador muestra por encima de la página y que bloquea la ejecución del script hasta que el usuario interactúa con ella. Existen tres diálogos nativos en JavaScript: alert, prompt y confirm. Cada uno cumple un papel distinto.

Función Propósito Qué devuelve
alert(msg) Mostrar un mensaje informativo undefined (nada útil)
prompt(msg, def) Pedir un texto al usuario string, "" o null
confirm(msg) Pedir una decisión sí/no true o false

2. alert() — mostrar mensajes

Muestra un mensaje y un botón Aceptar. No permite introducir datos. No devuelve nada útil (undefined).

alert("Hola mundo");

let curso = "JavaScript";
alert("Estás aprendiendo " + curso);

alert(`Hola, ${curso} 👋`);   // template literal
Error habitual Crees que alert devuelve el mensaje porque lo ves. No lo hace: devuelve undefined. Si haces let x = alert("hola"), x vale undefined.

3. prompt() — pedir datos al usuario

Muestra un campo de texto. El usuario puede escribir algo, aceptar sin escribir o cancelar. Siempre devuelve un string (o null si cancela).

prompt(mensaje, valorPorDefecto);
Acción del usuarioDevuelveTipo
Escribe y pulsa Aceptar"su texto"string
Acepta sin escribir""string vacío
Pulsa Cancelar / Escnullnull
let nombre = prompt("¿Cómo te llamas?");
alert("Hola, " + nombre);

// Con valor por defecto:
let ciudad = prompt("¿Dónde vives?", "Madrid");
¡El error número 1 en JavaScript! 
let a = prompt("num1");   // "5"
let b = prompt("num2");   // "3"
alert(a + b);              // "53" ❌ no es 8
Porque prompt devuelve strings y + con strings concatena. Solución: Number(prompt("num1")).

4. Conversión de tipos: la pieza clave

Como prompt siempre devuelve un string, si quieres operar matemáticamente con el dato, debes convertirlo:

ConversiónResultadoCuándo usarla
Number(x)número, o NaN si no es válidoCuando esperas enteros o decimales
parseInt(x, 10)entero truncadoCuando solo interesa la parte entera
parseFloat(x)decimalCuando esperas decimales con coma flotante
let a = Number(prompt("num1"));   // si escribe 5 → 5
let b = Number(prompt("num2"));   // si escribe 3 → 3
alert(a + b);                        // 8 ✅
Comportamiento curioso Number("") devuelve 0. Number("hola") devuelve NaN. Para detectar el segundo caso: isNaN(x) devuelve true.

5. confirm() — pedir una decisión

Muestra un mensaje con dos botones: Aceptar y Cancelar. Devuelve un booleano.

Acción del usuarioDevuelve
Pulsa Aceptartrue
Pulsa Cancelar / Escfalse
let ok = confirm("¿Seguro que quieres continuar?");

if (ok) {
  alert("Continuamos ✅");
} else {
  alert("Cancelado ❌");
}
Error frecuente con confirm 
// ❌ mal:
if (confirm("¿Borrar?") === "true") { ... }

// ✅ bien:
if (confirm("¿Borrar?")) { ... }
confirm devuelve el booleano true, no el string "true". Comparar con el string siempre da false.

6. Patrón combinado: pedir → validar → confirmar → mostrar

let nombre = prompt("¿Cómo te llamas?");

if (nombre === null || nombre.trim() === "") {
  alert("No escribiste un nombre.");
} else {
  let ok = confirm(`¿Confirmas que te llamas "${nombre}"?`);
  if (ok) {
    alert(`¡Bienvenido, ${nombre}! 🎉`);
  } else {
    alert("Vale, no guardaré ese nombre.");
  }
}
Memoriza este patrón prompt → validar (null, "", NaN) → confirm → alert. Lo usarás una y otra vez.

Solucionario — Ejercicio E

E1. El error es que a + b concatena porque ambos son strings ("5" + "3" = "53"), y "53" === 8 es falso. Corrección: 
if (Number(a) + Number(b) === 8) {
  alert("Es 8");
}
E2. Al cancelar, nombre es null y null.toUpperCase() lanza un TypeError, deteniendo el script. Corrección: 
let nombre = prompt("Tu nombre:");
if (nombre) {
  alert(nombre.toUpperCase());
} else {
  alert("No escribiste nombre");
}
null y "" son valores falsy, así que if (nombre) los descarta. Pero recuerda que el usuario sí podría haber querido escribir solo espacios: para eso, valida con nombre.trim() !== "".
E3. Usar prompt para una pregunta de sí/no es una mala elección porque el usuario puede escribir cualquier cosa (no hay restricción) y luego hay que parsear el texto. confirm está diseñado exactamente para eso. Corrección: 
let ok = confirm("¿Eliminar el archivo?");
if (ok) {
  alert("Eliminado");
}
E4. prompt devuelve string; "20" + 10 = "2010". Corregir convirtiendo: 
let edad = Number(prompt("Edad:"));
let futura = edad + 10;
alert("En 10 años tendrás " + futura);
E5. El else está invertido: el if (!ok) se ejecuta cuando el usuario pulsa Cancelar (ok = false → !ok = true). Pero el mensaje "Saliendo..." se muestra en el bloque del !ok, así que aparece cuando el usuario cancela, no cuando acepta. Corrección: 
if (ok) {
  alert("Saliendo...");
} else {
  alert("Sigues dentro");
}

Se ejecuta la primera rama (nombre === null), porque al cancelar prompt devuelve null exactamente. El usuario ve "Cancelaste".

Las comprobaciones van en ese orden por seguridad: null es el caso especial que hay que detectar primero. Si comprobáramos nombre === "" antes, null === "" es false y podríamos caer en la rama else sin querer. Además, si intentáramos hacer nombre.trim() sobre null, el script se rompería. Por eso siempre valida primero el null.

Solucionario — Ejercicio I

Hay muchas soluciones válidas. Esta es una posible, con todas las validaciones:

// 1. Nombre
let nombre = prompt("Nombre del cliente:");
if (!nombre || nombre.trim() === "") {
  alert("Nombre inválido");
} else {
  // 2. Edad
  let edad = Number(prompt("Edad:"));
  // 3. Entradas
  let n = Number(prompt("Número de entradas:"));

  if (isNaN(edad) || isNaN(n) || n < 1) {
    alert("Datos inválidos");
  } else {
    // 4. Menor de edad
    let menor = edad < 18;
    if (menor) {
      let acomp = confirm("Eres menor, ¿vas acompañado?");
      if (!acomp) {
        alert("No puedes entrar sin acompañante");
        // salir: podríamos envolver el resto en un if
      } else {
        let precio = menor ? 4 : 6;
        let total = precio * n;
        if (confirm(`Total ${total}€. ¿Confirmar reserva?`)) {
          alert(`Reserva OK: ${nombre}, ${n} entradas, ${total}€`);
        }
      }
    } else {
      let precio = 6;
      let total = precio * n;
      if (confirm(`Total ${total}€. ¿Confirmar reserva?`)) {
        alert(`Reserva OK: ${nombre}, ${n} entradas, ${total}€`);
      }
    }
  }
}

Puntos clave de evaluación: ¿validaste el null del nombre? ¿convertiste edad y entradas con Number? ¿validaste isNaN? ¿usaste confirm para las decisiones? ¿mostraste un resumen claro?

Solucionario — Ejercicio J

No hay respuestas "correctas" únicas: las respuestas personales dependen de cada alumno. Algunos ejemplos habituales:

J1. Los ejercicios más costosos suelen ser E1 (comparación string vs número) y D7 (comportamiento distinto de + y *). La razón habitual: intuimos que "JavaScript hace lo que queremos" y olvidamos que + es ambiguo.
J2. Un patrón frecuente: creer que confirm devuelve el texto del botón ("Sí"/"No"). La predicción falla porque confundimos lo que vemos (los botones) con lo que devuelve la función (un booleano). El antídoto es preguntarse siempre: ¿qué tipo de dato devuelve esta función?
J3. Reglas mnemotécnicas que suelen funcionar:
  • alert = "te aviso" (informativo)
  • prompt = "te pregunto un dato" (entrada de texto)
  • confirm = "te pido confirmación sí/no" (booleano)
  • Truco: alert → aviso · prompt → pido · confirm → confirmo.
J4. Antes de pasar a formularios HTML conviene dominar: (1) conversión string→número, (2) validación de null y isNaN, (3) if/else encadenado, (4) el patrón prompt → validar → confirm → alert. Con eso, el salto a addEventListener + document.getElementById es natural.
