0 Pre-test: lo que crees saber

Antes de aprender, intenta responder. Aunque falles, el intento prepara tu cerebro para aprender mejor (se llama efecto pretesting). No hay penalización.

PREDICCIÓN 1

¿Qué devuelve prompt() si el usuario pulsa "Cancelar"?

Confianza:
Respuesta: devuelve null. Si el usuario pulsa "Aceptar" sin escribir, devuelve un string vacío "".
PREDICCIÓN 2

¿Qué tipo de dato devuelve confirm()?

Confianza:
Respuesta: un booleano: true si pulsa Aceptar, false si pulsa Cancelar.
PREDICCIÓN 3

Si el usuario escribe 5 en un prompt y luego haces Number(x) + 3, ¿qué se obtiene?

Confianza:
Respuesta: 8. Number("5") convierte el string "5" en el número 5. Sin esa conversión, "5" + 3 daría "53".

1 ¿Qué es un diálogo modal?

Antes de ver las funciones, necesitas un modelo mental. Un diálogo modal es una ventanita que aparece encima de la página y bloquea todo hasta que el usuario interactúa con ella.

Dual coding: imagen mental + texto

Piensa en ello como tres cajitas que el navegador te ofrece:

// ┌──────────────────────────────────────┐
// │  🪟 DIÁLOGO MODAL (bloquea la página) │
// └──────────────────────────────────────┘
//    │             │             │
//    ▼             ▼             ▼
//  alert()      prompt()     confirm()
//   (salida)     (entrada)   (decisión)
🧩 Pregunta de elaboración ¿Por qué crees que el navegador bloquea la página entera mientras muestra uno de estos diálogos? ¿Qué problema ocurriría si no lo hiciera?
Ver razonamiento modelo

Porque el script necesita el resultado del usuario para continuar. Si el código sigue ejecutándose mientras el usuario aún no ha respondido, no sabría qué hacer con la respuesta. El bloqueo garantiza el orden de ejecución. La desventaja: congela toda la interfaz (por eso en apps reales se usan formularios HTML + DOM, que no bloquean).

El trío de funciones

FunciónPropósitoDevuelve
alert(msg)Mostrar informaciónundefined
prompt(msg, def)Pedir un textostring | "" | null
confirm(msg)Pedir sí/notrue | false

2 🔵 alert() — la salida más simple

alert() muestra una ventana con un mensaje y un botón "Aceptar". No devuelve nada útil (undefined). Es solo salida.

Ejemplo 1 — básico

alert("Hola mundo");

Ejemplo 2 — con variable

let curso = "JavaScript";
alert("Estás aprendiendo " + curso);

Ejemplo 3 — template literal (moderno y legible)

let nombre = "Ana";
alert(`Hola, ${nombre} 👋`);
⚠️ Buena práctica alert() es perfecto para aprender y depurar, pero no para producción: bloquea la página y no se puede estilizar. En apps reales se usa console.log() para depurar y elementos del DOM para mostrar mensajes.
PREDICCIÓN · ALERT

¿Qué mostrará exactamente este código?

let a = 2;
alert("Valor: " + a + 1);
Confianza:
Respuesta: "Valor: 21".
¿Por qué? Primero "Valor: " + 2 produce "Valor: 2" (string). Luego "Valor: 2" + 1 produce "Valor: 21" — el + con un string concatena, no suma.

🧩 Autoexplicación: escribe con tus palabras por qué a + 1 dentro de un alert con string delante no suma.

3 🟢 prompt() — pedir datos al usuario

prompt() muestra una ventana con un campo de texto. El usuario puede escribir, aceptar o cancelar. Siempre devuelve un string (o null si cancela).

Sintaxis

prompt(mensaje, valorPorDefecto);

El segundo parámetro es opcional. Si lo pones, aparece ya escrito en la caja.

Comportamiento exacto

Acción del usuarioDevuelveTipo
Escribe algo y pulsa Aceptar"su texto"string
Acepta sin escribir nada"" (string vacío)string
Pulsa Cancelar / Escnullnull

Ejemplo 1 — básico

let nombre = prompt("¿Cómo te llamas?");
alert("Hola, " + nombre);

Ejemplo 2 — con valor por defecto

let ciudad = prompt("¿Dónde vives?", "Madrid");

Ejemplo 3 — ¡el error clásico!

let a = prompt("Primer número");   // "5"  ← string
let b = prompt("Segundo número");  // "3"  ← string
alert(a + b);                              // "53" ❌ no es 8

Ejemplo 4 — conversión a número

let a = Number(prompt("Primer número"));
let b = Number(prompt("Segundo número"));
alert(a + b);   // 8 ✅

Ejemplo 5 — validación (nivel avanzado)

let entrada = prompt("Dime tu edad");

if (entrada === null) {
  alert("Cancelaste");
} else if (entrada.trim() === "") {
  alert("No escribiste nada");
} else if (isNaN(Number(entrada))) {
  alert("No es un número válido");
} else {
  alert(`Tienes ${entrada} años`);
}
🚨 Error típico Hacer nombre.toUpperCase() cuando nombre puede ser null romperá el script con "Cannot read properties of null". Siempre valida el null antes de operar.
PREDICCIÓN · PROMPT

El usuario escribe 7 en el primer prompt y 2 en el segundo. ¿Qué mostrará el alert?

let a = prompt("a");
let b = prompt("b");
alert(a * b);
Confianza:
Respuesta: 14.
El operador * convierte automáticamente los strings numéricos a números. "7" * "2" → 14.

Pero ojo: el + NO hace esto (concatena). Es la gran trampa del + en JS. 🧩 ¿Puedes explicar la diferencia entre + y * en una frase?

4 🟠 confirm() — pedir una decisión

confirm() muestra un mensaje con dos botones: Aceptar y Cancelar. Devuelve un booleano: true (Aceptar) o false (Cancelar / Esc).

Comportamiento exacto

Acción del usuarioDevuelve
Pulsa Aceptartrue
Pulsa Cancelar / Escfalse

Ejemplo 1 — básico

let respuesta = confirm("¿Seguro que quieres continuar?");

if (respuesta) {
  alert("Continuamos ✅");
} else {
  alert("Cancelado ❌");
}

Ejemplo 2 — directo (más compacto)

if (confirm("¿Eliminar el archivo?")) {
  alert("Borrado");
}
⚠️ Error común if (confirm("...") === "true") ❌ — compara un booleano con un string, siempre da false. confirm ya devuelve un booleano, no lo compares con texto.
🧩 Elaboración ¿Por qué confirm() no necesita un valor por defecto como prompt()? Pista: ¿cuántos tipos de respuesta puede dar el usuario?
PREDICCIÓN · CONFIRM

El usuario pulsa Cancelar. ¿Qué se muestra?

if (confirm("¿Sí?") === "true") {
  alert("A");
} else {
  alert("B");
}
Confianza:
Respuesta: "B".
Y aunque hubiera pulsado Aceptar, también saldría "B", porque true === "true" es false. Comparar booleano con string es un bug clásico. La forma correcta sería simplemente if (confirm("¿Sí?")).

5 🧩 Combinando las tres funciones

Ejemplo completo con flujo real: pedir datos → validar → confirmar → mostrar resultado.

// 1. ENTRADA
let nombre = prompt("¿Cómo te llamas?");

// 2. VALIDAR
if (nombre === null || nombre.trim() === "") {
  alert("No escribiste un nombre.");
} else {
  // 3. CONFIRMAR
  let ok = confirm(`¿Confirmas que te llamas "${nombre}"?`);

  // 4. MOSTRAR
  if (ok) {
    alert(`¡Bienvenido, ${nombre}! 🎉`);
  } else {
    alert("Vale, no guardaré ese nombre.");
  }
}
💡 Patrón mental prompt → validar → confirm → alert. Memoriza este patrón: lo usarás constantemente al aprender.

6 🔍 Análisis de errores (aprende de los bugs)

Detectar errores en código ajeno es una de las técnicas más potentes para construir un modelo mental robusto. Lee cada caso e identifica el bug antes de revelar la respuesta.

BUG 1 
let a = prompt("num1");
let b = prompt("num2");
alert(a + b);

El usuario escribe 5 y 3. Muestra "53". ¿Por qué está mal y cómo se arregla?

Bug: prompt devuelve strings, así que "5" + "3" concatena → "53".
Fix: Number(prompt("num1")) + Number(prompt("num2")).
BUG 2 
let nombre = prompt("Tu nombre:");
alert(nombre.toUpperCase());

Funciona bien si el usuario escribe. ¿Qué pasa si pulsa Cancelar?

Bug: al cancelar, nombre vale null. Llamar null.toUpperCase() lanza TypeError: Cannot read properties of null y detiene el script.
Fix: if (nombre) alert(nombre.toUpperCase()); (un null es falsy).
BUG 3 
if (confirm("¿Borrar?") === "true") {
  alert("Borrado");
}

El alert "Borrado" nunca se muestra, aunque el usuario pulse Aceptar. ¿Por qué?

Bug: confirm devuelve el booleano true, no el string "true". La comparación true === "true" es false.
Fix: if (confirm("¿Borrar?")).
